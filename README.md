# Project Environment & Test Runner

## Overview ✅

This repository includes an updated `requirements.txt` (secure and pinned versions), a `report.json` describing the package changes, environment setup scripts, Dockerfile, and `auto_test.py` to run tests using the active Python interpreter in VSCode (or an external system temp venv).

Files added or modified:
- `requirements.txt` — updated, pinned packages
- `requirements_backup.txt` — backup of the original list
- `report.json` — report of package updates and reasons
- `Dockerfile` — container image to run `auto_test.py`
- `setup.sh` — create external venv in system cache and install requirements (Linux/macOS)
- `run_test.sh` — wrapper to run `auto_test.py` (Linux/macOS)
- `run_test.bat` — wrapper to run `auto_test.py` (Windows)
- `auto_test.py` — creates external venv (if needed), installs requirements, runs tests, and writes logs
- `logs/test_run.log` — test run log (generated by auto_test.py)

---

## Quick start — Linux/macOS 🔧

1. Create an external venv and install requirements:

```bash
bash setup.sh
```

2. Run tests:

```bash
bash run_test.sh
```

Or run directly with your active Python interpreter (as selected in VSCode):

```bash
python3 auto_test.py
```

## Quick start — Windows ⚙️

1. Use the active Python interpreter (e.g., selected in VSCode) and run:

```powershell
python auto_test.py
```

2. Or run the batch wrapper:

```powershell
run_test.bat
```

## Docker 🐳

Build and run tests in Docker:

```bash
docker build -t myproject/test .
docker run --rm myproject/test
```

## Logs and results 📄

All output from test runs is written to `logs/test_run.log`.

## Notes & recommendations 💡

- This project assumes a Python 3.8+ interpreter; some updated packages require newer Python versions.
 - This project assumes a Python 3.8+ interpreter; some updated packages require newer Python versions.
 - Important: If your active interpreter is Python 3.14 (as detected on some hosts), many popular packages (numpy, scipy, lxml, etc.) may not yet provide prebuilt wheels for 3.14. In that case you have three recommended options:
	 1. Use Docker (recommended) — build the included Docker image (uses python:3.11) and run tests in that container.
	 2. Use conda to create a Python 3.11 environment and install the packages (conda provides prebuilt binaries).
	 3. Install Visual Studio Build Tools on Windows (MSVC) to compile packages from source — this is more involved and slower.
- `auto_test.py` will create a temporary venv under the system temp directory if it detects no active venv. The venv is not created within the project directory.
- If you prefer a persistent environment for development, run `setup.sh` which creates an external venv in the system cache.
